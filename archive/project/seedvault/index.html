SeedVault

🔐 SeedVault: On-Device Zero-Knowledge Security Vault

"Never trust a remote server. Trust only mathematics and your physical device."
"When regulatory hurdles halted the wallet project, we extracted its cryptographic heart and published it to the world."

SeedVault is an on-device, zero-knowledge security vault mobile application engineered to isolate and protect cryptocurrency mnemonic seed phrases, private keys, and sensitive credentials entirely offline on the user's hardware.

Originating as a response to complex Virtual Asset Service Provider (VASP) regulatory barriers that halted the parent SeedWallet project, all network and transaction modules were excised. The pure local cryptographic vault core was spun off and successfully published on the Google Play Store.

Project Background & Strategic Pivot

1. The Regulatory Obstacle of SeedWallet

The initiative originally started as SeedWallet, an ambitious multi-chain crypto wallet. However, it encountered significant non-technical barriers:

  • Stringent global licensing and financial compliance regulations (VASP requirements)
  • Prohibitive legal and security audit overhead for custodial systems
  • Unsustainable regulatory compliance liability for a solo indie developer

2. Redefining Value: From Wallet to Standalone Vault

Instead of abandoning the cryptographic foundations, focus was realigned onto the core thesis: "Empower users with the safest, trustless on-device mechanism to guard their private keys."

  • Excised all external RPC/node communication and internet permissions
  • Decoupled the cryptographic core into an independent package (@seedvault/crypto-core)
  • Pivoted into SeedVault, a zero-liability, 100% offline mobile utility published directly to Google Play

Core Security Architecture

[ 256-bit High-Entropy Key ]

        ├── (AES-256-GCM Encryption) ──► [ Encrypted Seed Envelope ]
        │                                  ├── Salt & Nonce/IV
        │                                  ├── Ciphertext
        │                                  └── Auth Tag
        │
        └── (Biometric Hardware Binding) ──► [ Capacitor Secure Storage ]

1. Argon2id Key Derivation Function (KDF)

  • Implements WebAssembly-powered Argon2id (hash-wasm) to resist GPU/ASIC brute-force cracking
  • Tunes memory cost, iteration counts, and concurrency parameters to deliver robust defense within mobile hardware thermal envelopes

2. AES-256-GCM Authenticated Envelope Encryption

  • Employs AES-256-GCM to ensure both confidentiality and tamper-proof data integrity
  • The EncryptedSeedEnvelope specification safely bundles ciphertext alongside unique salts, IVs, and authentication tags

3. Absolute Zero-Knowledge & Local-First Philosophy

  • No Backend: Data theft or server database breaches are architecturally impossible
  • Hardware Keystore Integration: Couples Capacitor Native Biometric and Secure Storage plugins to enable swift fingerprint/Face ID unlock while keeping master secrets locked in hardware

4. Air-Gapped QR Backup & Restoration

  • Employs an offline physical backup pipeline allowing users to export encrypted vaults without network connectivity
  • Compresses envelopes via Zlib (pako), encodes them into dense QR codes (qrcode), and supports direct restoration via camera scanning (jsqr)
