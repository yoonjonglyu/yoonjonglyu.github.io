## 배경

**ISA Util**은 프론트엔드 생태계 전반에서 반복적으로 발생하는 데이터 가공, 유효성 검증, 비동기 스케줄링 흐름에 일관된 인터페이스를 제공하기 위해 설계된 TypeScript 유틸리티 라이브러리입니다.

여러 프로젝트에 파편화되어 흩어져 있던 헬퍼 함수들을 체계적으로 통합하고, 완전한 타입 안정성과 견고한 테스트 가능성을 확립하는 것을 목표로 제작되었습니다.

---

## 문제 정의

다수의 프론트엔드 프로젝트를 진행하면서 다음과 같은 기술적 부채가 지속적으로 발생했습니다:

- 독립된 레포지토리마다 동일한 유틸 함수들이 **불필요하게 중복 구현**
- 검증되지 않은 매개변수와 **모호한 타입 스키마**로 인한 JavaScript 런타임 오류
- 테스트되지 않은 임시방편 래퍼 함수의 무분별한 사용
- 공통 로직을 수정할 때 여러 저장소를 동시에 리팩토링해야 하는 유지보수 병목

단순히 편의성 함수를 모으는 것을 넘어, **언제나 신뢰할 수 있는 공통 기반 레이어**가 필수적이라고 판단했습니다.

---

## 해결 전략

### 1. Type-First 아키텍처

모든 유틸리티 모듈은 입력 매개변수와 반환값 모두에 엄격한 계약(Contract)을 강제합니다:

- 컴파일 단계에서 논리적 오용을 즉각 차단
- 명확한 IDE 자동완성과 정밀한 타입 힌트를 통해 개발자 경험(DX) 극대화
- 함수 시그니처 자체가 살아있는 문서 역할을 하도록 설계

---

### 2. 도메인 주도 모듈화

필요한 모듈만 선별적으로 번들링할 수 있도록 단일 책임 원칙에 따라 분리했습니다:

- 타입 검증 (Type checking)
- 포맷팅 (Formatting)
- 비동기 제어 (`JobQueue`, `FlushQueue`, debounce, throttle)
- 스토리지 엔진 (LocalStorage 추상화, 타입 안전 IndexedDB 래퍼)
- 암호화 기본 요소 (Crypto primitives)
- 환경 및 플랫폼 감지 (Platform detection)
- DOM 헬퍼

---

### 3. 테스트 기반 신뢰성 확보

`Jest`를 활용하여 복잡한 실무 엣지 케이스를 철저히 검증하는 단위 테스트를 구축했습니다:

- 로케일별 날짜 템플릿과 숫자 파싱
- 논블로킹 비동기 작업 큐의 실행 순서 보장
- 대칭형 암호화/복호화 상태 정합성
- 플랫폼 환경 경계 조건 테스트

---

## 기술적 결정 및 이유

- **TypeScript**  
  → 유틸리티 라이브러리의 핵심 가치인 재사용성과 불변의 런타임 안정성을 보장하기 위해 필수 채택
- **Jest**  
  → 테스트 러너로서 빠른 피드백 주기와 정밀한 라인별 커버리지 측정을 위해 선정
- **Babel**  
  → 다양한 구형 브라우저 런타임 및 Node.js 서버 환경과의 완벽한 하위 호환성을 위해 트랜스파일 파이프라인 구성
- **NPM Package Registry**  
  → 분리된 여러 프로젝트와 마이크로서비스 간에 예측 가능한 시맨틱 버저닝 동기화를 위해 배포 체계 확립

---

## 결과 및 의의

- 프로젝트 간 공통 로직 중복 배제
- 엄격한 구조적 타입을 기반으로 견고한 공통 로직 레이어 확립
- 복잡한 UI 동시성을 안정적으로 처리하는 `JobQueue`, `FlushQueue` 등 실무 중심 비동기 워크플로우 축적
- 오픈소스 라이브러리의 구축 및 지속적 배포 운영 경험 내재화

ISA Util의 핵심 기준은 **“가장 작지만, 결코 무너지지 않는 기반 아키텍처를 세우는 것”**이었습니다.
