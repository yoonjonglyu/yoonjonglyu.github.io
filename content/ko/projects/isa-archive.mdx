## 배경

ISA Archive는 **자체 호스팅 기반의 엔지니어링 아카이브 및 이력서 플랫폼**으로 구상되었습니다.  
외부 서드파티 서비스에 의존하는 대신 포트폴리오 자체를 하나의 제품으로 다루며,  
**명확한 UI 아키텍처, 컴포넌트 재사용성, 구조화된 콘텐츠 관리**를 최우선으로 두었습니다.

주요 목표는 레이아웃, 데이터 모델링, 렌더링 전략에 대한 완전한 통제력을 유지하면서 **기술 문서, 프로젝트 기록, 이력서 데이터**를 단일 시스템 내에 통합하는 것이었습니다.

---

## UI 아키텍처 및 기술적 결정

### 컴포넌트 주도 UI 아키텍처 (CDD)

UI는 **컴포넌트 주도 개발(CDD)** 접근 방식을 따라 설계되었습니다.

- UI 컴포넌트는 페이지 합성 전에 독립적으로 개발 및 검증
- 상태 변형(비어있음, 로딩, 엣지 케이스)을 컴포넌트 레벨에서 정의
- 페이지 레이아웃은 비즈니스 로직을 담는 무거운 컨테이너가 아닌 얇은 합성 계층으로 기능

이러한 구조는 UI 복잡도가 페이지 로직을 통해 수직으로 증가하지 않고 컴포넌트를 통해 수평적으로 확장되도록 보장합니다.

---

### 디자인 시스템의 중추로서의 Storybook

`Storybook`은 **시각적 테스트 환경**이자 **살아있는 디자인 레퍼런스** 역할을 합니다.

- 격리된 렌더링 환경을 통해 리팩토링 중 레이아웃 회귀 방지
- 스토리를 통해 컴포넌트 동작을 암묵적으로 문서화
- 수동 QA 부담 없이 시각적 일관성 유지

---

### Styled Components를 통한 범위 제한 및 예측 가능한 스타일링

전역 스타일 오염과 네이밍 충돌을 피하기 위해 **CSS-in-JS 아키텍처**를 채택했습니다.

- 컴포넌트 단위 스타일 캡슐화
- `ThemeProvider`를 통한 테마 기반 스타일링
- 클래스명 충돌 없는 런타임 안전 동적 스타일링

---

### Contentlayer2 기반 정적 콘텐츠 파이프라인

전통적인 CMS 대신 **Contentlayer2 + MDX**를 정적 콘텐츠 파이프라인으로 사용합니다.

- MDX 파일을 단일 신뢰 원천(Single Source of Truth)으로 활용
- 구조화된 스키마로 콘텐츠를 타입 안전한 데이터로 변환
- 이력서 데이터와 아카이브 데이터가 동일 파이프라인을 공유하며 다양한 형태로 투영

---

### Next.js 16 및 정적 렌더링 전략

플랫폼은 정적 우선 원칙에 입각한 **Next.js 16 (App Router)** 기반으로 구축되었습니다.

- 예측 가능한 성능과 SEO를 위한 정적 생성(SSG)
- 클라이언트 런타임 로직 최소화
- 콘텐츠, 표현, 라우팅 간의 명확한 분리
